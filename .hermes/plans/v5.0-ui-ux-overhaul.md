# CyberDiviner v5.0 UI/UX 纠偏执行计划

## 差距分析摘要

| 类别 | 严重度 | 差距 |
|------|--------|------|
| ASCII Art UI | 🔴 严重 | 30+ 处使用键盘字符拼凑 UI (Pipe/Dash/Bracket) |
| Canvas 渲染 | 🔴 严重 | 卦象用 Box/Row 绘制, 图标用 ASCII Text |
| 字体打包 | 🔴 严重 | JetBrains Mono 和方正清刻本悦宋 均未打包 |
| 导航路由 | 🔴 严重 | 平面/遗留结构, RitualScreen 无法导航到工具页 |
| StrokeCap | 🔴 严重 | 零使用 StrokeCap.Square, 6处用 Round |
| Ripple 效果 | 🟡 中等 | 6+ 处 .clickable 使用默认 Material 水波纹 |
| 触觉反馈 | 🟡 中等 | HapticUtils 存在但从未被调用 |
| 版本号 | 🟡 低 | TerminalScreen 硬编码 "v4.0" |

## Phase 1: 基础组件 (1周)

### 1.1 字体打包
- 下载 JetBrains Mono Regular/Bold → app/src/main/res/font/
- 下载 方正清刻本悦宋 → app/src/main/res/font/
- 更新 Type.kt 使用打包字体

### 1.2 CyberButton 组件
- 无水波纹, 瞬发反色 (黑↔白)
- 按下时 HapticFeedbackType.TextHandleMove
- 松手恢复, 模拟终端闪烁

### 1.3 CyberMenuItem 组件
- 左对齐标题 + 英文副标题
- 点击反色 + 震动
- 用于 TerminalScreen 和 RitualScreen

### 1.4 Canvas 图标库
- I Ching: 八卦符号 (Canvas 绘制, StrokeCap.Square, 1-2.dp)
- Tarot: 卡牌轮廓
- Vision: 眼睛/雷达符号

### 1.5 HapticUtils 增强
- 添加 Compose Modifier 扩展: Modifier.cyberClick {}
- 统一触觉 + 视觉反馈

## Phase 2: 导航与静态页面 (1周)

### 2.1 NavGraph 重构
- 路由重命名: splash, terminal, agent_chat, ritual/iching, ritual/tarot, ritual/vision, archive_list
- 移除遗留路由
- 添加缺失的 composable 条目

### 2.2 TerminalScreen 重构
- 使用 CyberMenuItem 替代 Text
- 更新版本号 "v5.0"
- 添加进入动画

### 2.3 ArchiveScreen 重构
- 改为 "终端日志流" 视图 (LazyColumn)
- 单行格式: [timestamp] | HASH: 0x... | 状态
- 点击展开黑白电子存根

### 2.4 RitualScreen 重构
- 使用 Canvas 绘制工具图标 (替代 ASCII)
- 添加点击导航到 Liuyao/Tarot/Vision
- 添加 CyberMenuItem 样式

## Phase 3: 核心交互与 AI (2周)

### 3.1 打字机效果
- 基于协程的逐字显示 (20-50ms/字符)
- 输出期间微弱连续震动

### 3.2 AgentRepository
- 统一 JSON 协议
- 前端发送: 输入文本、位置、时间戳
- 后端返回: reply_text, require_more_info, soul_hash, ritual_result

### 3.3 Canvas 卦象渲染
- 6 个爻循环绘制
- 阳爻: 贯通线 (StrokeCap.Square, 2.dp)
- 阴爻: 两根断线 (中间留空 8.dp)

### 3.4 LiuyaoResultScreen 卦象重构
- 替换 Box/Row 为 Canvas 绘制

## Phase 4: 视界扫描与图文导出 (1周)

### 4.1 MediaPipe 面部特征点
- 黑白叠加层

### 4.2 电子存根 PNG
- 离线绘制 + 保存

## 执行策略

使用 Autonomous Dev Framework L4:
- Phase 1: 3 批次并行子代理
- Phase 2: 3 批次并行子代理
- Phase 3: 4 批次 (依赖链)
- Phase 4: 2 批次

每个 Phase 结束: 编译 → 安装 → 验证 → 提交
